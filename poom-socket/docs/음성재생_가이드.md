# 음성 비서 WebSocket 수신 오디오 재생 가이드 (프론트엔드)

## 왜 필요한가

서버에서 **작은 오디오 청크**를 여러 번 보냅니다.  
청크가 올 때마다 `play()`만 호출하면, 청크와 청크 사이에 **빈 구간**이 생겨 **뚝뚝 끊겨** 들립니다.

→ **다음 청크를 "이전 청크가 끝나는 시각"에 이어서 재생**하도록 스케줄해야 합니다.

---

## 필수 규칙 (스케줄 재생)

1. **다음 재생 시각**을 변수로 둔다 (예: `nextPlayTime`).
2. **청크를 받을 때마다**
   - 재생 시작 시각 = `max(현재 시각, nextPlayTime)`  
     (이미 지난 시각이면 바로 재생)
   - 해당 시각에 `start(when)`으로 재생
   - `nextPlayTime = when + (이 청크 재생 길이)`
3. **새로 연결할 때** (WebSocket 연결 시) `nextPlayTime`을 0으로 초기화.

---

## 재생 길이 계산

- 서버는 **24kHz, 모노, 16bit PCM**으로 보냅니다.
- `재생 길이(초) = (바이트 수 / 2) / 24000`  
  (2 = 16bit = 2 bytes per sample)

---

## 예시 (Web Audio API / JavaScript)

```javascript
const PLAY_RATE = 24000;  // 서버 출력 샘플레이트
let nextPlayTime = 0;     // 다음 청크 재생 시작 시각

// WebSocket 연결 시
nextPlayTime = 0;

// onmessage: 바이너리 청크 수신 시
function playChunk(audioContext, pcmInt16Array) {
  const float32 = new Float32Array(pcmInt16Array.length);
  for (let i = 0; i < pcmInt16Array.length; i++) {
    float32[i] = pcmInt16Array[i] / (pcmInt16Array[i] < 0 ? 0x8000 : 0x7FFF);
  }
  const duration = float32.length / PLAY_RATE;
  const when = Math.max(audioContext.currentTime, nextPlayTime);

  const buffer = audioContext.createBuffer(1, float32.length, PLAY_RATE);
  buffer.getChannelData(0).set(float32);

  const node = audioContext.createBufferSource();
  node.buffer = buffer;
  node.connect(audioContext.destination);
  node.start(when);

  nextPlayTime = when + duration;
}
```

- `audioContext.currentTime`: 재생 컨텍스트의 현재 시각(초).
- `node.start(when)`: `when` 시각에 재생 시작 (즉시 재생이면 `node.start(0)` 대신 `when`을 넣어서 이어 붙임).
